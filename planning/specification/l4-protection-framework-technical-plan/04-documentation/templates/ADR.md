# ADR-NNN: Short Decision Title

- Status: proposed | accepted | superseded | rejected
- Date: YYYY-MM-DD
- Owners/reviewers:
- Requirements/invariants:
- Supersedes/superseded by:

## Context

What concrete problem, constraint, and evidence require a decision? State what is out of scope.

## Decision drivers

Rank correctness, packet cost, latency, memory, operational fit, portability, implementation effort, compatibility, security, and reversibility as relevant.

## Considered options

For each serious option, describe behavior and measured/prototyped evidence. Include the simplest viable option.

## Decision

State exactly what will be implemented and at which boundary. Distinguish public semantics from internal choice.

## Consequences

Positive effects, costs accepted, new failure modes, dependencies, documentation/operations impact, and migration burden.

## Validation

Tests, models, benchmarks, hardware/software matrix, and quantitative pass criteria. Link raw result IDs rather than only a chart.

## Reversal triggers

Observable conditions under which this decision should be revisited. State viable fallback/migration path.

## Rollout

Incremental steps, compatibility plan, and how to return to the previous implementation safely.
